# Text engine, encoding, control codes

Addresses are CPU (HiROM: file offset = addr & 0x3FFFFF).

## Encoding (verified)

One code = one font cell; no Shift-JIS anywhere (relative search for いれてください finds nothing).

| Bytes | Meaning | Glyph |
|---|---|---|
| `00` | end of string (or return from a `{call}`) | |
| `01`-`0F` | control codes, below | |
| `10`-`44` | half-width (6 px) cells: space 0-9 A-Z ! ? … 、 。 ・ : + - × / = 「 」 『 』 | 12 B/glyph at `CA0000` (index = code-$10) |
| `45`-`4F` | past the end of the half-width font (unused) | |
| `50`-`F1` | full-width (12 px) cells 0-161: を, small kana, あ-ん, voiced, ヲ/small/ア-ン katakana, voiced, ヴ ー | 24 B/glyph at `CA027C` (index = code-$50) |
| `F2xx`-`FBxx` | full-width cells 162+: ■ then ~2460 kanji in JIS order by segments, then 々 ♪ 　 （ ） (last cell `FB9B`) | index = (code - $F15E) |

Glyph format (full width): 12 rows x 12 px, 1bpp, 24 bytes: bytes 0-11 = left 8 px of rows 0-11, bytes 12-23 = right 4 px (high nibble) of rows 0-11. Half width: 12 bytes, rows 0-11, left 6 px.

Table: `tbl/jp.tbl`, generated by `tools/fontmatch.py` (MS Gothic 12 px template match) + `tools/make_tbl.py` (kana order read off the font sheet, half-width set, control codes, `tbl/font_fixes.tsv` overrides). **Verified:** decoding the name-entry prompt and prologue matches the screen (`tests/test_text.py`); every unsure reading of a code the script uses (flagged by order, low score or small margin, 230 codes) was checked by eye on zoomed sheets (`tools/fontreview.py`) and the 22 wrong ones fixed. Readings the matcher was sure of (score margin >= 0.15) were not all checked by eye: a translator who meets a word that makes no sense should suspect a look-alike kanji. The font has 糧 twice (`F6D0`, `FAD2`); the second reads `‹糧›`.

## Engines (verified by exec hooks, `tools/lua/textlog.lua`)

- **Typed engine** `C318D1` (one code per frame into the dialogue box): pointer 24-bit at DP `$32-$34`, call stack at `$4774` (depth `$47A4`). Full-width glyph `C31979`, half-width `C31B74`; glyphs are drawn into a 2bpp buffer `$7E36DD` and DMAed by `C31AC5`/`C31CAE`. Characters sit on a **6 px grid**: a full-width cell is 12 px, half-width 6 px; `$474E` toggles the half-tile phase.
- **Bulk engine** `C32575` (whole string at once): prologue scroll, choice lists (`{choice}` builds them in `$7E498C`). Same codes, glyphs via `C32614`.
- Both share the control-code table `C3134B` (word per code).

## Control codes

Argument bytes follow the code. "verified" = handler read; "corpus" = decoded strings stay in sync.

| Code | tbl | Args | Meaning | State |
|---|---|---|---|---|
| `00` | `{end}` | 0 | end / return from call | verified |
| `01` | `{c01:1}` | 1? | handler `1D29` is entered with X 8-bit and runs into a BRK: never used in valid text | guess |
| `02` | `{wait}` | 0 | wait for a button, blinking ▼ | verified |
| `03` | `{delay:1}` | 1 | pause N frames | verified |
| `04` | `{var:1}` | 1 | insert a variable string (selector: `02` = hero name, `7E601A`+...) via the call stack | verified |
| `05`-`07` | `{c05}`... | 0 | no-op (RTS) | verified |
| `08` | `{sfx:1}` | 1 | `JSL C30316` with the arg (sound) | verified |
| `09` | `{c09}` | 0 | box mode 2: page break, keeps speaker? | guess |
| `0A` | `{clear}` | 0 | reset/clear the box | verified |
| `0B` | `{c0B}` | 0 | line break variant (scroll) | guess |
| `0C` | `{c0C}` | 0 | box mode 3: new page (used between speakers in one string) | guess |
| `0D` | `{nl}` | 0 | new line | verified |
| `0E` | `{choice:2}` | 2 | choice list: count, default; the options follow as text lines | verified (`C11AAA`) |
| `0F FF` | `{call:3}` | 3 | call string at 24-bit address (lo hi bank), return on `00` | verified |
| `0F FE` | `{icall:3}` | 3 | call the string whose 24-bit pointer sits at the address (`『{icall:2B4F7E}』` = hero name) | verified |
| `0F xx` | `{num:4}` | 4 | print a number: flags xx (low nibble = digits, bit 4/6/7 = size) then 24-bit address | partly (length from corpus) |

`{call}` makes relocation cheap: a string can be replaced in place by `0F FF <24-bit pointer> 00` (6 bytes) pointing at the English anywhere in the ROM, with no code change (guess until the marker build tries it).

## Where strings come from (pointer formats)

1. **Event scripts** (most dialogue): opcode `0A`/`0C` + flags byte + **16-bit pointer into the script's own bank** (`docs/re/events.md`). Verified: `E771BE: 0A 03 D3 78` shows `E778D3` (ガイアス cutscene, watch probe on the bytes).
2. **Code immediates:** `LDA #lo / STA $32 / LDX #bank / STX $34` (prologue `C16096` -> `C1621D`, then the following strings in order until `00 00`), or `LDA #lo / STA $4B90 / LDA #bank / STA $4B92` (name entry `C114A9` -> `C11A9C`).
3. **Fixed-width records:** item names in bank C6, 8-byte name field (`00`-padded) inside 18-byte records (`C6281F` ほしのこな, next `C62831`). Kana-only, drawn with the 8x8 menu font (`docs/re/graphics.md`).
4. **Common event table** `CE0128` (247 16-bit entries into bank CE, right after the scenario table): event scripts not in any scenario header (recruit/hire lines per character). Walked like scenario events.
5. **Menu-script VM** (building menus): interpreter `C0C4E7`, pointer 24-bit at DP `$72-$74`, op byte -> handler table `C0BF8F` (`FF` ends; `00 lo hi` goto). Menu ops `60`-`76` of the event VM set `$72` to a C1 script (`60` -> `C14094`). Its message op is also `0A ff lo hi` (bank C1). Scripts `C14094`-`C14D72`, their text `C14D73`-`C15DA4`. Opcode lengths not mapped (not needed: the text is one contiguous list).
6. **Pointer tables** (16-bit, own bank): ending scrolls `C17044` (5), ranks `C60E44`/`C60ECA`, armor types `C630C3`, monster retreat lines `C50ABE` (11), battle messages `C57CD8` (21; the shouts at `C57DCB`-`C57E02` are packed with no `00` between them, so a string ends at the next pointer), battle idle lines `C57E03` (7).
7. **Fixed-width name fields** in C6 records (`00`-padded; record stride differs per table): weapons `C60F50` (19 B), armor `C61CE5` (18), food `C62489` (12), items `C6253D` (18), items2 `C62BFD` (15), skills `C6368D` (13), beasts `C6686C` (37), named people `C674AE` (29), enemy classes `C6760C` (31), monster bosses `C679CF` (33). Width = longest name in the table for now; the menu code that reads them sets the real width (phase 5).

8. **Split lo/hi immediates:** `LDA #lo / STA $32 / LDA #hi / STA $33` (battle results `C34B9D`-`C34C5F`, bank C3).
9. **8x8 printer `{call}` wrappers in code banks:** `LDA #$A0D5 / STA $4F / JSL $C32912` where `C2A0D5` = `0F FF DB A0 C2 00` (calls `C2A0DB`); same at `C2A52A`.
10. **Tilemaps in LZ blocks** (8x8 font tiles, tile = code - $10): status/equip labels `CD51CD`, `CD5812` (`docs/re/graphics.md` G12); name grid `C7EAC9`. Not units yet.

All of these are units in `tools/extract.py` (`RUNS`, `PTRS`, `FIELDS`, `STRINGS`, `EVENT_TABLES`) -> `script/*.json`, except 10.

Coverage blind spot (found 2026-10-27): `extract.gaps` (the coverage test) skips hits with `{num`/`{var`/`{choice}`
codes and regions of fewer than 3 strings, so short code-adjacent lists slipped through (battle results, copier
warning `C15FA6`, `C03AEE`, the C2 wrappers). Swept by hand: uncovered textscan hits with a real word (2 kanji, kanji
+ 2 hiragana, or 4 katakana) are now all units or noise (bank CA and font sheets).

## Text ranges (survey, `tools/textscan.py`)

Strings that read as Japanese, by bank (regions of 3+ strings; noise in some banks): 8140 strings, ~347 KB.
Dialogue banks: **CE, CF, E3, E4, E5, E6, E7** (~30-37 KB each, event scripts plus text). Items/skills: **C6**. Code-adjacent strings: **C0, C1, C2, C3, C5**. **D6, D9** and others hold short hits that are partly noise (data that happens to decode). The extractor (phase 4) takes exact ranges from the event-script and code pointers, not from this scan.
